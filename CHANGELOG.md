# История изменений

## 1.0 — 23.11.2026

Версия с изменениями поведения: перед обновлением прочитайте раздел
«Что изменилось для существующих установок».

### Исправления

- **PostgreSQL-сборки Pangolin.** Тег `postgresql-X.Y.Z` (и `ee-postgresql-…`,
  суффиксы `-amd64`/`-arm64`) сохраняется при обновлении. Раньше он заменялся
  на обычный `X.Y.Z`, и Pangolin запускался SQLite-сборкой на пустой базе.
  Плавающие теги (`latest`, `1.26`) отвергаются с понятной ошибкой.
- **Прерывание в переходном состоянии.** Ошибка, Ctrl-C или `kill` после
  начала изменений больше не оставляют стек остановленным: обработчик выхода
  возвращает прежнее состояние (откат, запуск стека, откат установки CrowdSec).
- **Откат возвращает БД.** Если менялась версия Pangolin, при откате БД и
  `config.yml` восстанавливаются из архива, снятого перед обновлением: старая
  версия не запускается на схеме после миграций новой. Состояние после сбоя
  сохраняется в `BACKUP_DIR/failed_<дата>` для разбора.
- **`-info` с действием.** `-info -backup` и подобные сочетания теперь ошибка
  (код 4), а не молчаливое выполнение действия. Два действия сразу — тоже ошибка.
- **Чтение версий.** Строки `image:` распознаются с `docker.io/` и без, в
  кавычках и без; закомментированные строки и `traefik/whoami` больше не
  совпадают. Понятная ошибка вместо аварийного выхода, если строка не найдена.
- **Без понижения версий.** Сравнение по номерам версий, а не строк:
  установленный `1.27.0-rc.1` не «обновляется» до `1.26.0`.
- **Cloudflare:** IP контейнера при нескольких сетях больше не склеивается;
  JSON собирается через `jq`; файл с токеном не исполняется (`source`), а
  читается, и проверяются его права.
- **Ротация лога** не перезаписывает файл при второй ротации за день, старые
  логи сжимаются и удаляются (`LOG_KEEP`).
- **`*.bak.*`** больше не копятся бесконечно — хранится `BACKUP_KEEP` штук.
- **Восстановление** удаляет WAL-файлы новой базы перед распаковкой старой.

### Меньше простоя

- **Образы скачиваются до остановки.** Если образ не скачался или тег ещё не
  опубликован, обновление отменяется до любых изменений (код 4) — раньше стек
  останавливался, pull падал и запускался откат.
- **Горячая резервная копия** (`BACKUP_MODE=hot`, по умолчанию): БД SQLite
  копируется online backup API без остановки стека, затем `docker compose up -d`
  пересоздаёт только изменённые контейнеры. Для PostgreSQL и при
  `BACKUP_MODE=cold` — прежняя схема с остановкой. `--backup` тоже работает
  без простоя.
- **Health check** начинает опрос сразу и завершается, как только всё в
  порядке; один вызов `docker inspect` на все контейнеры.
- **Проба плагинов** завершается по ответу `/ping`, а не через фиксированные
  30 с; результат кэшируется на `PROBE_CACHE_HOURS`.
- **GitHub API:** повторы при сбоях, `GITHUB_TOKEN`, условные запросы по ETag,
  при недоступности — последний сохранённый ответ.
- **Cron-синхронизации:** если поддомены/адреса не изменились, Cloudflare и
  `cscli` не запрашиваются; зоны и записи Cloudflare читаются одним списком.
- **Установка CrowdSec** готовит и проверяет конфиги на копиях, пока стек
  работает; простой — перезапуск Traefik.

### Надёжность проверки

- Контейнер в состоянии `health: starting` считается ещё не готовым (раньше —
  здоровым). Контейнер без healthcheck должен проработать `HEALTH_MIN_UPTIME` с.
- Проверяются и остановленные контейнеры, и сервисы без контейнера.
- **HTTP-проверка через Traefik** (`dashboard_url` или `HEALTH_URL`). Включается,
  только если адрес отвечал до изменений — без ложных откатов.
- Ошибка пробы «не удалось проверить» (нет сети, нет образа) отличается от
  «плагины не загрузились».

### Безопасность

- Lock через `flock` в `/run` вместо PID-файла в `/tmp` (нет гонки и
  symlink-атаки); cron-синхронизации не пересекаются друг с другом и с обновлением.
- Архивы — права 600, каталог бэкапов — 700, проверка `gzip -t`, проверка
  свободного места до изменений. Лог — 640.
- Архив включает `.cf-dns.env`.
- Вместо `docker image prune -a -f` удаляются только заменённые образы.
- `yq` и `crowdsec-manager` закреплены по digest.
- **CrowdSec:** `crowdsec-manager` ставится только с `--with-manager`;
  `clientTrustedIPs` пуст по умолчанию (`CROWDSEC_CLIENT_TRUSTED_IPS`); ключ
  bouncer хранится в файле (`crowdsecLapiKeyFile`); ротация access-лога без
  `copytruncate` (Traefik переоткрывает лог по USR1).
- Внешний IP сервера принимается, только если его подтвердили два сервиса.
- Токен Cloudflare аргументом — предупреждение; рекомендуемый способ —
  переменная `CLOUDFLARE_API_TOKEN`.

### Эксплуатация

- **Файл конфигурации** `/etc/pangolin-update.conf` — настройки переживают
  обновление скрипта (образец — `pangolin-update.conf.example`).
- **Уведомления:** ntfy (`NOTIFY_URL`), Telegram, своя команда (`NOTIFY_CMD`);
  heartbeat в формате healthchecks.io (`HEARTBEAT_URL`).
- **Коды выхода:** добавлен 4 — «ничего не изменено».
- **Политика:** `MIN_RELEASE_AGE_HOURS` (по умолчанию 24), запрет мажорных
  обновлений Pangolin/Gerbil/Badger без `ALLOW_MAJOR_UPGRADE`, `--no-delay`.
- **`--hold` / `--unhold`** — пауза обновлений.
- **`--dry-run`** — diff файлов, которые будут изменены.
- **`PRUNE_MODE=previous`** — предыдущая версия образов хранится до следующего
  успешного обновления.
- Cloudflare: обновление IP в своих записях, `CF_TARGET_IP=auto`,
  `CF_DELETE_STALE`.
- Allowlist: `ALLOWLIST_NEWT`, `ALLOWLIST_NEWT_EXCLUDE`.
- Основные опции в форме `--long`; однодефисные формы работают как раньше.

### Разработка

- `main()` и защита от запуска при `source` — функции можно тестировать.
- Тесты `bats`: модульные и интеграционные (имитация docker), CI на GitHub Actions
  (ShellCheck + тесты).

### Что изменилось для существующих установок

1. Настройки, которые вы меняли в начале скрипта, перенесите в
   `/etc/pangolin-update.conf`.
2. Новые релизы ставятся через 24 часа после выхода. Прежнее поведение:
   `MIN_RELEASE_AGE_HOURS=0`.
3. Резервная копия перед обновлением делается без остановки стека. Прежнее
   поведение: `BACKUP_MODE=cold`.
4. Старые образы удаляются при следующем успешном обновлении, а не сразу, и
   только образы стека. Прежнее «удалить сразу»: `PRUNE_MODE=immediate`
   (`docker image prune -a` скрипт больше не вызывает).
5. `--restore` без терминала требует `-y`.
6. Новые установки CrowdSec: без crowdsec-manager (добавьте `--with-manager`)
   и без доверенных частных сетей в `clientTrustedIPs`. Уже установленный
   CrowdSec не меняется.
7. Имена архивов и `*.bak.*` — `YYYYMMDD_HHMMSS`; старые имена тоже
   учитываются при очистке.
8. Нужен `flock` (пакет util-linux, есть почти везде) и Bash 4.4+.

## 0.9 — 27.10.2026

`-crowdsec-install` — установка CrowdSec + AppSec + crowdsec-manager в уже
работающий Pangolin одной командой: проверки и проба плагина до простоя,
полный бэкап, правка YAML через yq в контейнере (комментарии сохраняются),
регистрация bouncer, health check с автоматическим откатом, logrotate,
allowlist + cron; `-crowdsec-uninstall` — обратная операция; `-y`.

## 0.8

Автоматический allowlist CrowdSec для своей инфраструктуры: публичные IP
сервера и сайтов Newt (из БД Pangolin, только активные сайты); устаревшие
автоматические записи удаляются, ручные не трогаются; `-allowlist-sync`,
`-allowlist-on`, `-allowlist-off`.

## 0.7

Поддержка CrowdSec (+ AppSec) и crowdsec-manager: обновление образа CrowdSec в
своей мажорной ветке, обновление правил Hub (`-crowdsec-hub`), проба загружает
все плагины Traefik, `HEALTH_IGNORE_SERVICES`, логи Traefik не попадают в бэкап.

## 0.6

обновления, проверка логов Traefik в health check, частичный откат только
Badger, контроль версии Badger после миграции Pangolin, `BADGER_PIN`, запись
версии только внутри блока `badger:`.
